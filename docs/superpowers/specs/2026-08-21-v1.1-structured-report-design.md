# v1.1 结构化分析报告

> 状态：已实现  
> 日期：2026-08-21  
> 范围：v1.1 四块中的第三块（结构化分析报告）。Watchlist、研报夹页面不在本文。Onboarding、仪表盘已另有 spec。  
> 相关：`ChatView.tsx` 消息块、`agent/core.py` system prompt、`FIN_AGENT_CHOICES_JSON`、`user_profile.experience_level`

## 1. 目标

个股体检、组合诊断、买卖决策备忘录在聊天里以固定报告卡片出现，并按 `experience_level` 切简版 / 适中 / 完整。卡片可收藏完整副本到本地；研报夹浏览 UI 留 v1.2。

## 2. 非目标

- 研报夹列表 / 检索 / 个股页历史分析（v1.2）
- Watchlist、仪表盘改版、投资日历
- 用户在卡片上切换简版/完整（深度只跟画像，当场不可改）
- 云同步、自动测试、Mock
- 独立 `/reports` 页面

## 3. 已确认决策

- 三种报告本轮都做；自由提问只要判定是这三类分析，一律出报告卡；闲聊、查行情仍是普通 Markdown
- 「该不该买/卖、能不能上车、止损设哪」→ 买卖决策备忘录；一般「分析这只股票」→ 个股体检；组合诊断/体检 → 组合诊断
- 共用章节：结论 → 依据 → 风险 → 下一步；ROADMAP 里的内容写进「依据 / 下一步」，不另起一套一级标题
- 深度跟画像：`beginner` 简版（少表、解释术语），`experienced` 完整（含指标表），`Unknown` 适中；章节不删
- 实现路径：模型在正文末尾附 `FIN_AGENT_REPORT_JSON`（同快捷选项标记），Python 抽出后变成助手消息的 `report` 区块
- 收藏：卡片按钮，完整 JSON 副本写入配置目录；删会话后收藏仍在；成功后按钮变「已收藏」，再点取消

## 4. 出现时机

助手完成一轮回复后，若抽出合法 `FIN_AGENT_REPORT_JSON`，该条消息渲染报告卡。

必须出卡：

| kind | 用户意图（示例，不穷举） |
|------|--------------------------|
| `stock_checkup` | 分析 / 体检某只股票、个股基本面技术面 |
| `portfolio_diagnose` | 组合诊断、组合体检、持仓健不健康 |
| `trade_memo` | 该不该买/卖、能不能上车、仓位与止损 |

不出卡：问候、查现价、设提醒、纯工具确认、新闻闲聊等。模型不得给这些回复附加报告标记。

仪表盘「分析一只股票 / 组合体检」预填句仍走现有 `requestPrefill`；预填文案须点明对应 `kind`，使模型带上标记。

## 5. 界面

### 5.1 报告卡片

在助手消息中，分析正文被报告卡替换（工具调用块、思考块仍保留）。卡片自上而下：

- 类型标签：个股体检 / 组合诊断 / 买卖决策备忘录
- 标题：如「贵州茅台 个股体检」
- 深度标签：简版 / 适中 / 完整（只读）
- 按钮「收藏」；已收藏为「已收藏」，再点取消
- 四个章节标题固定为「结论」「依据」「风险」「下一步」，正文用现有 Markdown 渲染
- 底部免责声明：「以上内容仅供参考，不构成投资建议。」

涨跌色、`fa-card`、`--fa-*` 与现网一致，不引入新视觉体系。

### 5.2 流式

生成过程中仍按 Markdown 流出，行为与现网一致。整轮结束后抽出 JSON：

- 合法 → 追加 `report` 块，并从该条消息的 text 块中去掉标记行；分析正文改由卡片展示，避免和卡片重复
- 缺失或损坏 → 保持普通 Markdown，无卡片、无收藏

### 5.3 快捷选项

`FIN_AGENT_CHOICES_JSON` 仍可出现在报告类回复末尾，解析规则不变。报告标记与快捷选项标记是两行，互不替代。

## 6. 数据与 API

### 6.1 报告 JSON（模型输出）

正文最后一行（或最后出现的标记，与 CHOICES 相同取法）：

`FIN_AGENT_REPORT_JSON` + 紧凑 JSON 对象。

```json
{
  "kind": "stock_checkup",
  "title": "贵州茅台 个股体检",
  "depth": "brief",
  "symbols": ["600519.SH"],
  "portfolio_id": null,
  "sections": {
    "conclusion": "……",
    "evidence": "……",
    "risk": "……",
    "next": "……"
  },
  "disclaimer": "以上内容仅供参考，不构成投资建议。"
}
```

| 字段 | 规则 |
|------|------|
| `kind` | 仅 `stock_checkup` \| `portfolio_diagnose` \| `trade_memo` |
| `title` | 非空中文标题 |
| `depth` | `beginner`→`brief`；`experienced`→`full`；`Unknown`→`standard`。模型按当前画像填写，前端不改 |
| `symbols` | 个股/备忘录至少 1 个 ts_code；组合诊断可为空数组 |
| `portfolio_id` | 仅组合诊断填写，其他为 `null` |
| `sections.*` | 四个键都须为非空字符串；允许内含 Markdown |
| `disclaimer` | 固定免责句；缺则前端补上固定文案 |

Python 校验：`kind` 枚举、四章节非空。不校验「依据是否真的覆盖了基本面」——那靠 prompt。闲聊误带合法 JSON 仍出卡（靠 prompt 约束，不做第二套分类器）。

`stream_chat` 对报告标记的处理与 CLI 过滤 `FIN_AGENT_CHOICES_JSON` 同一思路：内容流里不要把标记行发给前端；校验通过后额外 `yield {"type": "report", "report": {…}}`。ChatView 收到 `report` 事件后写入该条助手消息的 `report` 块。前端不必再扫一遍正文。标记未通过校验则不 yield `report`，正文保持普通 Markdown。

### 6.2 三种报告必须写进章节的内容

章节名不改。下列内容写进「依据」或「下一步」：

- **个股体检**：基本面、技术面、估值；完整版在依据中加指标表
- **组合诊断**：行业分布、集中度、盈亏归因、与风险偏好是否匹配；下一步给调仓建议
- **买卖备忘录**：看多或看空理由、支撑/压力位；下一步给建议仓位与止损参考

简版少表、解释术语；完整版给表；适中介于二者。

### 6.3 System prompt

在现有「分析结构 / 经验分层」上增加：

- 三类意图必须输出 `FIN_AGENT_REPORT_JSON`，且 `kind`/`depth` 与上表一致
- 非三类意图禁止该标记
- 标记行不要包在代码围栏里

现有预填（`buildAnalyzeStockPrefill` / `buildPortfolioDiagnosePrefill`）补一句要求对应 `kind`。新增 `buildTradeMemoPrefill`，供明确买卖意图复用（本轮不强制新入口按钮）。

### 6.4 收藏存储

文件：与 `user_profile.json` 同一配置目录下的 `analysis_favorites.json`。

```json
{
  "items": [
    {
      "id": "uuid",
      "created_at": 0,
      "kind": "stock_checkup",
      "depth": "brief",
      "title": "……",
      "symbols": ["600519.SH"],
      "portfolio_id": null,
      "sections": { "conclusion": "", "evidence": "", "risk": "", "next": "" },
      "disclaimer": "以上内容仅供参考，不构成投资建议。",
      "source_session_id": "……"
    }
  ]
}
```

- `POST /reports/favorites`：body 为报告 payload + 可选 `source_session_id`；成功返回 `{ ok: true, id }`
- `DELETE /reports/favorites`：body `{ "id": "..." }`；成功 `{ ok: true }`
- 本轮不提供列表 UI；不实现按股票检索

收藏成功后把 `favorite_id` 写回该条消息的 `report` 块，随 `save-session-ui` 持久化，刷新后仍显示「已收藏」。

IPC：`save-analysis-favorite` / `delete-analysis-favorite`。preload 与 `env.d.ts` 同步。不要加入 `_CSRF_PROTECTED_PREFIXES`。

### 6.5 前端块类型

`ChatBlock` 增加：

```ts
{
  type: 'report'
  kind: 'stock_checkup' | 'portfolio_diagnose' | 'trade_memo'
  title: string
  depth: 'brief' | 'standard' | 'full'
  symbols: string[]
  portfolio_id?: string | null
  sections: { conclusion: string; evidence: string; risk: string; next: string }
  disclaimer: string
  favorite_id?: string
}
```

新建 `ReportCard.tsx`，由 `ChatView` 在 `block.type === 'report'` 时渲染。不要再挂一套会话。

## 7. 错误处理

- 标记缺失、JSON 非法、缺章节、`kind` 非法：当普通 Markdown，不弹错误条
- 收藏 / 取消失败：`alert` 中文原因，卡片仍在，按钮状态不改
- Python 未就绪：与现网一致，发消息仍等后端
- 不使用 Mock 占位报告

## 8. 验收（手动）

不写自动测试、不生成 Mock、不编译。

1. 空会话点「分析一只股票」并选中后，回复是个股体检报告卡（简版/适中/完整与当前画像一致），不是「今天想分析什么？」
2. 无持仓点「组合体检」仍先提示添加；有持仓发出诊断后是组合诊断报告卡
3. 输入「茅台该不该买」出买卖备忘录卡；输入「现在几点了」或「茅台现价」不出卡
4. 新手画像下个股卡带「简版」、少指标表；改成老手后再分析，带「完整」和指标表
5. 未点收藏时配置目录无对应条目；点「收藏」后 `analysis_favorites.json` 有完整副本；删掉该会话文件后条目仍在；再点「已收藏」条目删除，按钮恢复
6. 人为让模型不输出标记（或截断）：仍能看到普通 Markdown，无收藏按钮
7. 报告卡下方快捷选项仍可用（若模型给了 `FIN_AGENT_CHOICES_JSON`）
