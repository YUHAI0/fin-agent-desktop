# Fin-Agent Desktop v1.0.2 设计说明

> 状态：待实现  
> 日期：2026-08-14  
> 相关：`ROADMAP.md`（v1.0.2 节）

## 1. 目标与原则

**定位不变**：智能投资顾问；v1.0.2 延续 v1.0.1「现有能力打磨」思路，不引入大型新模块。

**本版本目标**：

1. 股价提醒触发后，全渠道展示**语义化、带股票名称**的可读文案。
2. 新增 Agent 工具 **`query_news`**，按需从 akshare **实时拉取**全量快讯，支持多维度筛选。

**原则**：

- 独立模块、职责清晰（`alert_copy.py`、`news_query.py`）
- `query_notified_news`（本地已推送）与 `query_news`（实时拉取）职责分离，不合并为单一工具
- 复用现有 Electron + Python Agent 架构，不新增独立服务或页面模块

**明确不在本版本**：新闻结果写入本地库 / 资讯流 UI；Tushare 概念板块替代 akshare；投资仪表盘、Watchlist、定时简报。

## 2. 范围清单

### 2.1 股价提醒文案优化

- 新增 `alert_copy.py`，集中生成提醒文案
- 全渠道统一：Toast、提醒列表、触发历史、邮件、Agent 工具返回
- 文案始终包含 **股票名称 + 代码**
- 百分比提醒持久化元数据，文案可表达「较设置时上涨 X%」
- `alert_history.json` 新增 `message`、`condition_label` 字段
- `ReminderTasksModal` 优先展示 `condition_label`

### 2.2 全量新闻查询

- 新增 Agent 工具 `query_news`
- 实时从 akshare 拉取：`stock_info_global_cls`、`stock_info_global_em`、`stock_news_em`
- 筛选维度：内容关键词、板块（关键词 + 成分股关联）、指定股票、时间、数量
- 板块成分股：akshare 东财概念/行业板块（`stock_board_concept_cons_em` 等）
- 时间：相对（`days` / `hours`）与绝对（`start_date` / `end_date`）；同时传时以绝对日期为准
- 新增 `news_query.py` 查询服务；`query_notified_news` 保持不变

## 3. 架构

在 v1.0.1 三层架构上扩展：

```text
Renderer
  ReminderTasksModal   → 展示 condition_label / message
  ToastView            → 接收语义化 title / body（无需改结构）
       ↓ IPC
Main                   → REST 转发（无新 IPC，复用现有 scheduler API）
       ↓
Python fin-agent
  alert_copy.py（新）   → format_alert(task, stock_name, current_price)
  scheduler.py          → 触发时调用 alert_copy；写入 history
  news_query.py（新）   → 拉取 + 过滤 + 去重
  news_tools.py         → query_news 工具入口
  api.py                → price-alert-pct 写入百分比元数据
  Agent core            → 工具指引区分 query_notified_news / query_news
```

### 3.1 方案选型

采用 **独立模块 + 单一 Agent 工具**（方案 B）：

- 不内联至 `scheduler.py` / 不合并 `query_notified_news`
- 便于单测与后续 v1.1 仪表盘「待关注事项」复用文案模块

## 4. 股价提醒文案 — 详细设计

### 4.1 任务元数据扩展

`tasks.json` 中 `price_alert` 任务可选字段（旧任务缺省按绝对价处理）：

| 字段 | 类型 | 说明 |
|------|------|------|
| `alert_mode` | `"absolute"` \| `"pct"` | 默认 `"absolute"` |
| `base_price` | number | 创建时参考价；百分比提醒必填 |
| `pct` | number | 百分比幅度 |
| `direction` | `"up"` \| `"down"` | 百分比方向 |

**写入时机**：

- `POST /scheduler/tasks/price-alert-pct`：创建时写入 `alert_mode="pct"` 及 `base_price`、`pct`、`direction`
- Agent `add_price_alert`：仍为 `alert_mode="absolute"`（或省略）

### 4.2 文案数据结构

```python
@dataclass
class AlertCopy:
    title: str            # Toast / 邮件标题
    body: str             # Toast / 邮件正文（较短）
    condition_label: str  # 列表/历史条件摘要
    message: str          # 完整一句描述
```

**入口**：`format_alert(task, *, stock_name: str, current_price: float) -> AlertCopy`

### 4.3 文案规则

所有文案前缀：`{stock_name}({ts_code})`。

| 场景 | condition_label 示例 | message 要点 |
|------|---------------------|--------------|
| `operator >= threshold`，绝对价 | 突破 20.50 元 | 价格已**突破** 20.50 元，当前 {price} 元 |
| `operator > threshold`，绝对价 | 超过 20.50 元 | 价格已**超过** 20.50 元，当前 {price} 元 |
| `operator <= threshold`，绝对价 | 回落至 15.00 元及以下 | 价格已**回落到** 15.00 元及以下，当前 {price} 元 |
| `operator < threshold`，绝对价 | 跌破 15.00 元 | 价格已**跌破** 15.00 元，当前 {price} 元 |
| `alert_mode=pct`，direction=up | 上涨 {pct}% 至 {threshold} 元 | 较设置时（{base} 元）**上涨** {pct}%，当前 {price} 元 |
| `alert_mode=pct`，direction=down | 下跌 {pct}% 至 {threshold} 元 | 较设置时（{base} 元）**下跌** {pct}%，当前 {price} 元 |

**标题示例**：`股价提醒：宁德时代(300750.SZ)`

**列表展示**：`{stock_name} {ts_code} · {condition_label}`

### 4.4 各渠道写入

| 渠道 | 改动 |
|------|------|
| Toast `notification_sink` | `title` = `AlertCopy.title`，`body` = `AlertCopy.body` |
| 邮件 subject / 正文 / HTML | 使用 `message` 及结构化字段 |
| `alert_history.json` | 追加 `message`、`condition_label`；保留 `operator`、`threshold` |
| `list_tasks_enriched` | 每条任务附加 `condition_label`（基于 task 元数据预生成，不含 current_price） |
| `list_alerts`（Agent） | 输出含 `condition_label` 的中文行 |
| `ReminderTasksModal` | 条件列优先 `condition_label`，历史优先 `message` |

### 4.5 边界与兼容

- 触发时无 `stock_name`：从 `get_realtime_price` 补全
- 旧 `alert_history` 无 `message`：前端 fallback `价格 {operator} {threshold}`
- 百分比元数据缺失：按绝对价规则生成
- 价格格式：保留 2 位小数（与现有 UI 一致）

## 5. 全量新闻查询 — 详细设计

### 5.1 工具签名

```python
def query_news(
    query=None,          # 标题/摘要关键词；与 keywords 等价
    keywords=None,       # 字符串数组；多词 AND 匹配
    sector=None,         # 板块名，如「低空经济」
    sector_mode="both",  # "keyword" | "constituents" | "both"
    ts_code=None,        # 指定股票 → stock_news_em
    sources=None,        # 省略则按场景自动选择
    days=None,           # 最近 N 天
    hours=None,          # 最近 N 小时；与 days 互斥，hours 优先
    start_date=None,     # YYYY-MM-DD
    end_date=None,       # YYYY-MM-DD
    limit=20,            # 1–50
)
```

**时间优先级**：若 `start_date` 或 `end_date` 存在，忽略 `days` / `hours`。

### 5.2 拉取策略

```text
ts_code 有值
  → AkshareNewsAdapter.fetch_stock_symbol(ts_code)

ts_code 无值
  → 拉 global 源（CLS + EM，或 sources 指定）

sector_mode ∈ {constituents, both}
  → ak.stock_board_concept_cons_em(sector) 取成分股
  → 全局快讯 symbols 与成分股交集；或标题/摘要含板块名

sector_mode ∈ {keyword, both}
  → 全局快讯标题/摘要匹配 sector 或 keywords

keywords / query
  → 标题+摘要 AND 匹配（casefold）
```

**默认源**：

| 条件 | 默认 sources |
|------|--------------|
| 指定 `ts_code` | `stock_news_em` |
| 仅板块/关键词 | `stock_info_global_cls`, `stock_info_global_em` |
| 显式 `sources` | 用户指定（校验 `SUPPORTED_NEWS_SOURCES`） |

### 5.3 过滤、去重、排序

1. 解析 `published_at`，按时间窗过滤；解析失败则保留条目
2. 关键词：全部词 AND
3. 板块成分：symbol 交集或文本含板块名
4. 去重：`NewsItem.fingerprint`
5. `published_at` 降序，取前 `limit` 条

### 5.4 返回格式

```json
{
  "ok": true,
  "data": {
    "items": [
      {
        "id": "stock_info_global_cls:xxx",
        "title": "...",
        "summary": "...",
        "url": "...",
        "published_at": "2026-08-14T10:30:00+08:00",
        "source": "stock_info_global_cls",
        "symbols": ["300750.SZ"]
      }
    ],
    "total": 12,
    "fetched_from": ["stock_info_global_cls"],
    "filters_applied": {
      "sector": "低空经济",
      "days": 3,
      "limit": 20
    }
  }
}
```

失败时：`{"ok": false, "error": "友好中文 + 替代建议"}`（如建议 `query_notified_news`）。

### 5.5 性能与限制

- 板块成分股 > 30：仅取前 30 只做 symbol 匹配；不全量逐股拉新闻
- `limit` 上限 50
- akshare 请求复用现有重试（`akshare_provider._with_retry` 或同等机制）
- **不写入** `NotifiedNewsStore`；不更新资讯流 UI

### 5.6 Agent 指引

`agent/core.py` system prompt 补充：

> 查本地已推送/订阅匹配新闻 → `query_notified_news`；按需查全量快讯、指定股票或板块新闻 → `query_news`。

`toolDisplayName.ts` 增加 `query_news` 中文名（如「全量新闻查询」）。

## 6. 错误处理

| 场景 | 行为 |
|------|------|
| akshare 拉取失败 | 中文原因 + 建议缩小范围或查 `query_notified_news` |
| 板块名未找到 | 提示检查板块名称；若 `sector_mode=both` 仍尝试关键词匹配 |
| 时间范围内无结果 | 返回空列表 + `total: 0`，不报错 |
| 提醒触发时行情缺失 | 不触发；与现有逻辑一致 |
| 旧任务无元数据 | 按绝对价文案规则降级 |

## 7. 非目标与依赖后续版本

- 新闻查询结果持久化 / 资讯流展示 → 后续版本
- 仪表盘「待关注事项」接入提醒文案 → v1.1
- Tushare `get_concept_detail` 作为板块成分备选 → 可选增强，非 v1.0.2 必做
- 情感分析、订阅联动 → 不在本版本

## 8. 验收要点（手动）

1. 绝对价提醒触发后，Toast / 邮件 / 历史均显示带股票名称的语义化文案。
2. 百分比提醒创建后，`tasks.json` 含 `alert_mode=pct` 等元数据；触发文案含「较设置时上涨/下跌 X%」。
3. 提醒列表展示 `condition_label`，非 `价格 > 20.5` 技术格式。
4. Agent 调用 `query_news(ts_code="300750.SZ", limit=10)` 返回实时个股新闻。
5. Agent 调用 `query_news(sector="低空经济", days=3)` 返回板块相关快讯。
6. `query_notified_news` 行为与 v1.0.1 一致，不受影响。
7. 无 Tushare Token 时 `query_news` 仍可正常工作（纯 akshare）。
