## 1. 概述

1. 数据源抽象层 + akshare 接入（akshare 转为默认数据源）

5. 投资组合 v2（多组合 + 元数据 + UI 增删改查）
6. 版本号升级到 1.1.10

| 前端 | React 18 + TypeScript + Tailwind + react-router-dom（HashRouter） |

## 2. 横切改动

### 2.1 api.py 路由表重构

`api.py` 的 `do_GET` / `do_POST` 目前是巨型 `if/elif` 链，7 个端点已占约 350 行，且 JSON 解析、`try/except`、状态码、响应头这套模板在每个分支重复。本次要新增 16 个端点，继续堆 `elif` 不可维护。

改造为字典分发：

```python
ROUTES = {
    ("GET",  "/config"):          handle_get_config,
    ("GET",  "/sessions"):        handle_list_sessions,
    ("POST", "/sessions/rename"): handle_rename_session,
    # ...
}
```

约束：

- 每个 handler 签名统一为 `handler(req) -> dict`，返回值由分发器序列化。`req` 为一个简单容器，含 `req.query`（由 URL 查询串解析，GET 使用）与 `req.body`（由请求体 JSON 解析，POST 使用）。分发器按 `urlparse` 的 path 部分匹配路由，查询串不参与匹配。
- handler 抛异常时，分发器统一返回 `500` 与 `{"error": str(e), "trace": ...}`，保持与现有响应结构一致。
- handler 需要返回非 200 状态码时，抛出 `ApiError(status, message)`。
- `POST /chat` 因需手动控制 SSE 流式写入，**保留为特例**，不进路由表。
- 现有 7 个端点的**请求与响应结构不变**，仅迁移实现位置，确保 preload / main 层无需改动。

### 2.2 新增配置项

写入 `{config_dir}/app_config.json`（与现有 `wake_up_shortcut` 同类，均为行为开关而非密钥）：

| 键 | 类型 | 默认 | 说明 |
|---|---|---|---|
| `data_source` | string | `"akshare"` | 取值 `akshare` / `tushare` |
| `alert_poll_interval_minutes` | int | `10` | 取值范围 1–120 |
| `alert_trading_hours_only` | bool | `true` | 为 true 时仅在 A 股交易时段轮询 |

`GET /config` 与 `POST /config/save` 的载荷相应增加这三个字段；`src/renderer/src/env.d.ts` 的 `ConfigData` 类型同步扩展。

### 2.3 模块依赖与交付顺序

| # | 模块 | 依赖 |
|---|---|---|
| 1 | 数据源抽象层 + akshare | 无 |
| 2 | 多会话与历史抽屉 | 无 |
| 3 | 提醒轮询间隔 + 交易时段 | 模块 1（交易日历） |
| 4 | 关于 / 支持页 | 无 |
| 5 | 投资组合 v2 | 模块 1（批量实时行情） |
| 6 | 版本号 | 模块 1–5 全部完成 |

模块 1、2、4 无相互依赖，可并行实施。模块 3 与 5 需等模块 1 的 provider 接口定稿。

## 3. 模块 1：数据源抽象层 + akshare

### 3.1 目标

引入 provider 抽象，使 akshare 成为默认数据源，无 Tushare Token 的用户可直接使用核心行情与财务功能。

### 3.2 接口定义

新建包 `python/fin-agent/fin_agent/datasources/`：

```
datasources/
  __init__.py          # 注册表与 get_provider()
  base.py              # MarketDataProvider 抽象基类、异常定义
  tushare_provider.py
  akshare_provider.py
  normalize.py         # 代码与列名归一化工具
```

`base.py`：

```python
class CapabilityNotSupported(Exception):
    """当前 provider 不支持该能力。"""

class MarketDataProvider(ABC):
    name: str
    CAPABILITIES: set[str]

    def get_stock_basic(self, ts_code=None, name=None) -> pd.DataFrame: ...
    def get_daily_price(self, ts_code, start_date, end_date, adj=None) -> pd.DataFrame: ...
    def get_realtime_price(self, ts_code: str | list[str]) -> pd.DataFrame: ...
    def get_daily_basic(self, ts_code, start_date, end_date) -> pd.DataFrame: ...
    def get_income_statement(self, ts_code, start_date, end_date) -> pd.DataFrame: ...
    def get_index_daily(self, ts_code, start_date, end_date) -> pd.DataFrame: ...
    def get_trade_calendar(self, start_date, end_date) -> pd.DataFrame: ...
```

设计要点：

- **返回 `pandas.DataFrame` 而非 JSON 字符串。** 序列化由上层工具函数统一完成，provider 只负责取数与归一化。
- **`get_realtime_price` 接受单个代码或代码列表。** akshare 实现使用全市场快照接口一次取回后本地过滤；Tushare 实现内部仍逐个请求，对上层透明。此设计为模块 5 的组合估值性能所必需。
- **`get_trade_calendar` 不暴露为 LLM 工具**，仅供模块 3 判断交易日。
- **`CAPABILITIES` 用于前置检查。** 工具层在调用 provider 前先比对该集合，未声明的能力直接抛 `CapabilityNotSupported`，避免走到底层才失败。

### 3.3 数据归一化

以 **Tushare 格式为基准**，理由是现有系统提示、工具描述、`portfolio.json` 中存储的代码均为该格式，更换基准波及面过大。

| 项目 | 基准格式 |
|---|---|
| 股票代码 | `600519.SH` / `000001.SZ` |
| 日期 | `YYYYMMDD` 字符串 |
| 行情列名 | `ts_code, trade_date, open, high, low, close, pre_close, change, pct_chg, vol, amount` |

akshare 使用纯数字代码、中文列名、`YYYY-MM-DD` 日期，全部转换逻辑封装在 `akshare_provider.py` 与 `normalize.py` 内部，不外泄。

### 3.4 注册与切换

`datasources/__init__.py` 提供：

```python
def get_provider() -> MarketDataProvider
```

按 `app_config.json` 的 `data_source` 返回实例并按名称缓存。配置变更时清除缓存。

### 3.5 工具层改造

新建 `fin_agent/tools/market_tools.py`，承载六个核心工具的薄封装：调用 `get_provider()`、序列化 DataFrame、捕获 `CapabilityNotSupported` 并转为中文引导语。

`tushare_tools.py` 的处理：

- 六个核心函数（`get_stock_basic`、`get_daily_price`、`get_realtime_price`、`get_daily_basic`、`get_income_statement`、`get_index_daily`）的实现迁移至 `tushare_provider.py`，工具入口改由 `market_tools.py` 提供。
- 其余 Tushare 专属工具（选股筛选、港股、美股、ETF、可转债、期货、宏观、龙虎榜、涨停、资金流、概念、业绩预告等）**保持原实现不动**，仅统一加上 `@requires_tushare` 装饰器。
- `TOOLS_SCHEMA` 的聚合方式不变，仅调整 `execute_tool_call` 中六个核心工具的分发目标。

`@requires_tushare` 装饰器行为：检测 `Config.TUSHARE_TOKEN` 为空时，直接返回中文提示（例如"该功能需要 Tushare Token 才能使用，请在设置页填写后重试"），不调用底层接口、不抛异常。

### 3.6 系统提示改造

`agent/core.py` 的 `_get_system_content()` 中以下内容需修改：

- `"You are a financial assistant powered by LLM and Tushare"` 改为数据源无关的措辞。
- `"All market data MUST be obtained via Tushare tools"` 改为 `"...via the provided market data tools"`。
- **动态追加可用性说明**：当 `Config.TUSHARE_TOKEN` 为空时，在系统提示中明确列出当前不可用的工具名，避免模型反复尝试调用注定失败的工具。

### 3.7 设置页

`ConfigView.tsx` 的"金融数据"区块：

- 新增数据源下拉：`akshare（免费，推荐）` / `tushare`，默认 akshare。
- Tushare Token 输入框保留且始终可编辑，下方说明文字：填写后可解锁选股筛选、港美股、可转债、期货、宏观数据等增强功能。

### 3.8 依赖与打包

**已核实的事实**：akshare 从 1.16.72 到 1.18.81 的**所有版本**在非 Linux 平台均硬依赖 `mini-racer`（用于 JS 解密部分接口），Windows wheel 为 14.8MB，解压后内嵌 V8 体积更大。不存在可规避该依赖的 akshare 版本。

akshare 在 Windows 上的完整依赖链：`mini-racer`、`curl_cffi`、`lxml`、`beautifulsoup4`、`html5lib`、`openpyxl`、`xlrd`、`urllib3`、`tqdm`、`jsonpath`、`tabulate`、`decorator`，外加 akshare 自身约 10MB 源码。

决定：

- `requirements.txt` 增加 `akshare`，**锁定为 `akshare==1.18.81`**（实施时若有更新版本可评估后调整）。
- **接受 `mini-racer`**，不尝试通过 PyInstaller `excludes` 排除。理由：akshare 的 `__init__.py` 为全量 eager import，排除后极可能导致 `import akshare` 整体失败，收益（约 15MB）与风险不匹配。
- `requirements.txt` 移除 `schedule`（模块 3 不再使用）。
- 仅做常规精简：在 `make.py` 的 `pyinstaller_cmd` 中追加 `--exclude-module` 参数，排除确认与运行无关且非 akshare 依赖的模块。**不得排除 `xlrd`**（akshare 硬依赖）；`matplotlib` 本就不在依赖链中，无需处理。
- 注意：精简参数必须写在 `make.py` 而非 `api.spec`。`make.py` 以命令行参数直接调用 PyInstaller，不读取 spec 文件；且 `api.spec` 已被 `.gitignore` 的 `*.spec` 规则忽略，不纳入版本管理。
- 安装包增量**预期 30–45MB**（NSIS 压缩后），不设硬性指标。打包与体积实测由项目维护者执行，结果回填至本文档。

### 3.9 手动验收清单

1. 清空 `.env` 中的 `TUSHARE_TOKEN`，启动应用，询问"茅台现在多少钱"，应正常返回实时价格。
2. 询问"帮我筛选 PE 小于 20 的股票"，应返回"需要 Tushare Token"的中文引导，而非报错或堆栈。
3. 设置页切换数据源为 tushare 并填入有效 Token，重复第 1 步，应正常返回。
4. 分别在两种数据源下查询同一只股票的日线，确认返回的代码格式与列名一致。
5. 打包一次，记录安装包体积增量并回填至 3.8 节。

## 4. 模块 2：多标签会话与历史保留

### 4.1 目标

支持多个会话标签并行使用，会话历史跨应用重启完整保留，并提供带搜索的历史抽屉。

### 4.2 UI 形态

采用**顶部标签栏 + 历史抽屉**：

- **标签栏**位于标题栏下方，显示当前打开的会话，每个标签带关闭按钮，末尾为 `＋` 新建。
- **历史抽屉**由标签栏左上角 `☰` 触发，从左侧浮出（宽约 280px，带半透明遮罩），内含搜索框与按时间分组的会话列表；点击某项以新标签打开。
- 聊天区始终保持满宽，不被常驻侧栏挤压。

选择该方案的理由：窗口仅 900px 宽，金融对话常包含表格，横向空间敏感；历史检索属低频操作，按需浮出优于常驻。

### 4.3 存储结构

```
{config_dir}/sessions/
  index.json            # 元数据索引
  <session_id>.json     # 单个会话正文
```

`index.json`：

```json
{
  "version": 1,
  "sessions": [
    {
      "id": "uuid",
      "title": "贵州茅台估值",
      "created_at": 1785926446,
      "updated_at": 1785926900,
      "pinned": false,
      "message_count": 12,
      "preview": "帮我看看茅台现在的估值水平"
    }
  ]
}
```

`preview` 为首条用户消息的前 40 字，供列表项的二级文本展示。

列表、分页、排序、置顶、重命名**只读写 `index.json`**，不加载正文，保证常数开销。

`<session_id>.json`：

```json
{
  "id": "uuid",
  "llm_history": [],
  "ui_messages": []
}
```

**两份数组并存**：`ui_messages` 含 `thinking` / `tool_execution` 等渲染块，`llm_history` 含 `tool_calls` 等模型协议字段，两者无法无损互转。各自独立存储，避免转换损失。

新建 `fin_agent/session_store.py` 封装全部读写，包括索引与正文的一致性维护。

`agent/core.py` 现有的 `save_session` / `load_session` **保留方法签名，内部改为委托 `session_store`**。这两个方法被 CLI（`fin_agent/main.py` 的 348、359、364、375 行）调用，直接删除会破坏命令行入口。CLI 继续操作固定的 `last_session.json` 会话，不参与多标签逻辑。

### 4.4 请求流程

1. 前端 `POST /chat` 携带 `session_id`。
2. Python 从磁盘加载该会话的 `llm_history`。
3. **每个请求新建一个 `FinAgent` 实例**并注入历史（`FinAgent.__init__` 仅构造 LLM 客户端并读取一次 `user_profile.json`，开销可忽略），随后流式输出。
4. 流结束后写回 `llm_history`，更新 `index.json` 的 `updated_at` 与 `message_count`。
5. 前端渲染完成后单独调用 `POST /sessions/ui`（请求体含 `id` 与 `ui_messages`）保存渲染数据。

因每请求独立实例，**多个标签可真正并行生成，互不干扰**，无需全局锁或忙碌提示。

### 4.5 会话标题

首轮对话结束后，在后台线程用一句短提示请 LLM 总结 12 字以内标题，写入 `index.json`。失败或模型未配置时回退为首条用户消息截断（前 20 字），确保标题永不为空。

### 4.6 新增端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/sessions` | 列表，查询参数 `offset` / `limit`；置顶优先，其余按 `updated_at` 倒序 |
| GET | `/sessions/detail` | 查询参数 `id`，读取单个会话正文 |
| POST | `/sessions/create` | 新建会话，返回 `id` |
| POST | `/sessions/delete` | 删除会话（索引与正文一并删除） |
| POST | `/sessions/rename` | 重命名 |
| POST | `/sessions/pin` | 切换置顶 |
| POST | `/sessions/search` | 全文搜索 |
| POST | `/sessions/ui` | 保存 `ui_messages` |

**全文搜索限流**：最多扫描最近 200 个会话正文，且累计耗时超过 2 秒即截断并返回已命中结果（响应中带 `truncated: true`），避免会话积累后卡住 UI。

### 4.7 必须移除的现有行为

`src/main/index.ts` 中 `window-all-closed` 与 `before-quit` 触发的 `clearChatHistory()` 必须移除——它会在退出时向渲染进程发送 `clear-chat-history` 清空历史，与本模块目标直接冲突。渲染层对应的监听逻辑一并移除。

### 4.8 旧数据迁移

首次启动 1.1.10 时，若检测到 `localStorage` 中存在 `fin-agent-chat-history` 且非空：将其内容包装为一个标题为"历史对话"的会话写入新结构，随后删除该 key。迁移只执行一次，通过写入标记位判断。

### 4.9 手动验收清单

1. 新建三个标签，分别提问不同问题，确认互不串话。
2. 在两个标签中几乎同时发问，确认两边都能正常流式输出。
3. 完全退出应用并重启，确认三个会话均在历史抽屉中，打开后消息完整（含工具调用块的渲染）。
4. 重命名、置顶、删除各操作一次，重启后状态保持。
5. 搜索一个只在某会话正文中出现过的词，确认能命中该会话。
6. 用 1.1.10 之前的版本产生若干聊天记录，升级后确认自动生成"历史对话"会话且内容完整。

## 5. 模块 3：轮询间隔配置与交易时段感知

### 5.1 存量 bug 修复

`init_agent()` 中执行 `TaskScheduler().start()` 启动 daemon 线程，而 `POST /config/save` 每次都会重新调用 `init_agent()`——**用户每保存一次设置就会多出一个调度线程**，导致重复检查与重复发送提醒邮件。

修复：将调度线程收敛为模块级单例，配合 `threading.Event` 作停止信号；`init_agent()` 重入时检测到线程已存在则跳过启动。

### 5.2 调度循环改造

移除 `schedule` 库，改为朴素循环：

```python
timeout = 0
while not stop_event.wait(timeout):
    cfg = Config.get_app_config()
    if not cfg.get("alert_trading_hours_only", True) or is_trading_now():
        self.check_conditions()
    timeout = cfg.get("alert_poll_interval_minutes", 10) * 60
```

收益：间隔变更在下一周期自动生效，无需重启应用；停止信号可干净退出；`schedule` 依赖可从 `requirements.txt` 移除，抵消部分 akshare 体积增量。

### 5.3 交易时段判定

`is_trading_now()` 规则：

- 时段：`09:15–11:30` 与 `12:55–15:05`（含集合竞价与收盘缓冲），按本地时间判断。
- 日期：通过模块 1 的 `get_trade_calendar` 判断是否交易日，结果**按天缓存**。
- 降级：交易日历获取失败时退化为"周一至周五"的静态判断。

### 5.4 设置页

"系统"区块新增：

- 数字输入框：轮询间隔（分钟），范围 **1–120**，默认 10。低于 1 分钟对本地轮询无意义且易被数据源限流。
- 开关：仅在交易时段轮询，默认开启。开关下方需明确说明："关闭后将 7×24 小时轮询"，避免用户困惑于周末提醒不触发。

### 5.5 手动验收清单

## 7. 模块 5：投资组合 v2

### 7.1 数据模型

`{config_dir}/portfolio.json` 新格式：

```json
{
  "version": 2,
  "active_portfolio_id": "default",
  "portfolios": {
    "default": {
      "name": "默认组合",
      "created_at": "2026-08-05T12:00:00",
      "positions": {
        "600519.SH": {
          "amount": 100,
          "cost": 1680.5,
          "bought_at": "2026-01-15",
          "note": "核心底仓"
        }
      }
    }
  }
}
```

`bought_at` 与 `note` 均为可选，缺省为空。

### 7.2 迁移

`PortfolioManager._load_portfolio()` 检测到文件**无 `version` 字段但有顶层 `positions`** 时，将其整体包装进 `default` 组合（名称"默认组合"），补齐 `version: 2` 与 `active_portfolio_id` 后写回。旧持仓的 `amount` 与 `cost` 原样保留，`bought_at` 与 `note` 留空。

### 7.3 add 与 update 语义分离

两者必须并存：

| 方法 | 语义 | 入口 |
|---|---|---|
| `add_position` | **累加**（加权平均成本），保持现有行为 | LLM 工具（"再买 100 股茅台"） |
| `update_position` | **覆盖**（直接写入指定值） | UI 编辑（手动修正数量或成本） |

新增签名：`update_position(portfolio_id, ts_code, amount, cost, bought_at, note)`。

### 7.4 批量实时行情

现有 `get_portfolio_status` 逐个调用 `get_realtime_price`，每个 3 秒超时——10 个持仓最坏需等待 30 秒。改为一次性传入全部代码，调用模块 1 的批量接口。akshare 走全市场快照后本地过滤，一次请求即可。

同时移除 `portfolio.py` 顶部的 `from fin_agent.tools.tushare_tools import get_realtime_price`，改为通过 `get_provider()` 获取。

### 7.5 LLM 工具改造

`add_portfolio_position`、`remove_portfolio_position`、`get_portfolio_status`、`clear_portfolio` 四个 schema 各增加一个**可选** `portfolio` 参数；不传时作用于 `active_portfolio_id`。这样"看我的持仓"行为不变，同时支持"看我波段仓的盈亏"。

### 7.6 新增端点

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/portfolio/list` | 组合列表（不含估值） |
| POST | `/portfolio/create` | 新建组合 |
| POST | `/portfolio/rename` | 重命名组合 |
| POST | `/portfolio/delete` | 删除组合 |
| GET | `/portfolio/detail` | 查询参数 `id`，返回该组合的持仓 + 实时估值汇总 |
| POST | `/portfolio/position/add` | 新增持仓，供 UI 使用 |
| POST | `/portfolio/position/update` | 编辑持仓（覆盖语义） |
| POST | `/portfolio/position/delete` | 删除持仓 |

约束：

- 删除最后一个组合时应拒绝并返回提示，保证至少存在一个组合。
- `/portfolio/position/add` 供 UI 的"添加持仓"使用，若该 `ts_code` 在目标组合中**已存在则拒绝**，并提示改用编辑。它与 LLM 工具 `add_portfolio_position` 的累加语义是两条独立路径，不共用实现。

### 7.7 UI

新增路由 `/portfolio` 与组件 `PortfolioView.tsx`，采用**卡片列表**布局：

- 顶部：组合切换 Tab + `＋` 新建组合。
- 其下：汇总卡（总市值、总盈亏 + 收益率）。
- 主体：持仓卡片列表，每张卡包含名称/代码、数量·成本、现价·市值、买入日·备注、盈亏金额与比率，右侧常驻编辑与删除按钮。
- 新增与编辑复用同一弹窗组件。

选择卡片列表的理由：新模型下字段增至 11 项，900px 宽度内表格会导致备注截断与单元格拥挤；卡片布局所有信息不截断，且更易适配窄窗口。

入口：ChatView 顶部工具栏新增按钮，与现有提醒任务入口并列。

### 7.8 手动验收清单

1. 准备一份旧格式 `portfolio.json`，启动应用，确认自动迁移为"默认组合"，且持仓数量与成本不变。
2. 新建"波段仓"组合，添加两只持仓，切换 Tab 确认两个组合数据独立。
3. 编辑某持仓的数量与成本，确认为覆盖而非累加。
4. 对 AI 说"再买 100 股茅台"，确认为累加且成本被加权平均。
5. 对 AI 说"看我波段仓的持仓"，确认返回的是波段仓而非默认组合。
6. 组合内放入 10 只持仓，确认页面在数秒内完成估值加载。
7. 尝试删除最后一个组合，确认被拒绝并有提示。
